# 데이터 이행 검증

데이터 이행 전후에 추출한 두 CSV 파일을 KEY 기준으로 대조하고, 일치·변경·추가·삭제 내역을 확인하는 데스크톱용 검증 도구입니다. 컬럼명이 다르거나 숫자·날짜의 표기가 다른 경우에는 컬럼 매핑과 비교 규칙을 지정할 수 있습니다. 필요한 경우 SQL로 비교 대상을 가공한 뒤 검증합니다.

모든 데이터 처리는 사용자 PC의 브라우저 내 DuckDB-WASM에서 수행합니다. CSV 데이터를 서버로 업로드하지 않으며, 정적 파일을 제공하는 내부 웹 서버만으로 운영할 수 있습니다.

## 1. 적용 범위

| 항목 | 내용 |
|---|---|
| 검증 대상 | 기준 데이터 Source와 이행 후 비교 데이터 Target에서 추출한 CSV |
| 검증 기준 | 단일 또는 복합 KEY, 매핑한 컬럼, 컬럼별 비교 규칙 |
| 판정 결과 | 일치 `MATCH`, 변경 `MODIFIED`, 추가 `ADDED`, 삭제 `DELETED` |
| 결과 확인 | 건수 카드, 상태 필터, 50건 단위 페이지 조회, 컬럼별 상세 비교 |
| 결과 파일 | 단일 검증 CSV 4종, 일괄 검증 Excel(요약·불일치 상세·검증 기준) |
| 실행 방식 | 브라우저에서 로컬 처리, 별도 백엔드·DB 서버·외부 API 불필요 |
| 화면 환경 | 데스크톱 전용, 최소 작업 폭 1100px |

이 도구는 추출된 CSV 간의 데이터 대조를 수행합니다. 원본 DB에 직접 접속하거나 데이터를 수정·이행하지 않으며, 업무 규칙에 따른 별도의 품질 검증은 검증 범위에 맞게 준비해야 합니다.

| 데이터 확인 | 접이식 컬럼 목록과 최대 20행 미리보기, NULL과 빈 문자열 구분 |

| 컬럼 매핑 | 같은 이름의 컬럼 자동 연결, 수동 추가·삭제, 서로 다른 컬럼명 연결 |

| 상세 결과 | KEY·상태·변경 컬럼 표시, 기준 값과 비교 값의 좌우 대조, 변경 컬럼 강조 |

| Excel 결과 | 일괄 검증의 요약·불일치 상세·검증 기준을 하나의 `.xlsx` 파일로 다운로드 |

## 3. 사용 절차

### 3.1 파일 선택

1. **기준 파일(Source)**과 **비교 파일(Target)**을 선택합니다.
2. 첫 번째 행이 컬럼명이 아니면 해당 파일의 체크를 해제합니다.
3. 행 수·컬럼 수를 확인하고, 필요하면 **컬럼 및 데이터 미리보기**를 펼칩니다.
4. 파일을 교체하려면 다시 선택하고, 제거하려면 파일명 오른쪽의 `×`를 누릅니다.

### 3.2 SQL 가공 — 선택 사항

각 파일의 **SQL로 가공**을 펼치면 테이블명 입력칸과 기본 SQL이 표시됩니다.

```sql
-- 기준 파일의 기본 SQL
SELECT * FROM "source";

-- 비교 파일의 기본 SQL
SELECT * FROM "target";
```

테이블명을 변경하면 기본 SQL도 변경됩니다. 사용자가 직접 작성한 SQL은 덮어쓰지 않습니다. 테이블명은 문자 또는 `_`로 시작하고 문자·숫자·`_`를 사용할 수 있으며 한글도 지원합니다. 양쪽 이름은 대소문자를 구분하지 않고 서로 달라야 하며, 앱 내부에서 사용하는 이름은 제한합니다. 예약어를 이름으로 쓰면 큰따옴표로 감쌉니다.

예를 들어 기준 파일에서 다음 SQL을 적용하면 활성 데이터만 선택하고 컬럼명을 비교 파일에 맞출 수 있습니다.

```sql
SELECT
    USER_ID AS USER_NO,
    USER_NAME,
    CAST(AMOUNT AS INTEGER) AS AMOUNT
FROM source
WHERE STATUS = 'Y';
```

SQL의 테이블 참조 기준은 다음과 같습니다.

| 참조 대상 | 조회하는 데이터 |
|---|---|
| 자기 쪽 테이블명 | 처음 불러온 원본 CSV. 반복 적용해도 이전 가공 결과에 누적하지 않음 |
| 다른 쪽 테이블명 | 그쪽의 현재 데이터. 가공했다면 가공 결과 |
| 기본 이름 `source`·`target` | 사용자 지정 이름과 함께 계속 사용 가능 |

다른 쪽 파일을 불러온 경우 Source에서 Target을 참조하거나 조인할 수 있으며, 반대 방향도 가능합니다. **SQL 적용** 후 미리보기·매핑·비교·다운로드는 가공 결과를 사용합니다. 가공 결과의 컬럼은 문자열로 저장합니다. 실패하면 현재 데이터는 유지되며, **원본으로 되돌리기**로 가공 전 CSV를 복원할 수 있습니다. SQL은 조회 결과를 만드는 단일 쿼리로 실행하며, 세미콜론 뒤에 두 번째 명령문을 붙이면 오류로 거부됩니다.

### 3.3 컬럼 매핑과 KEY 검증

1. 이름이 같은 컬럼은 대소문자를 구분하지 않고 자동 연결됩니다.
2. 이름이 다르면 **+ 매핑 추가**로 연결합니다. 예: `USER_ID` ↔ `USER_NO`.
3. 레코드를 식별할 KEY를 하나 이상 선택합니다. 여러 개를 선택하면 복합 KEY입니다.
4. 필요한 컬럼에 비교 규칙을 지정합니다. **사용자 정의 SQL 식**을 고르면 행 아래에 Source 변환식 입력칸이 열립니다. 식을 입력한 뒤 **변환식 확인**을 눌러 전체 Source 행의 계산 가능 여부와 앞 5행의 원본값·기대값을 확인합니다. 매핑하지 않은 컬럼은 비교에서 제외됩니다.
5. **KEY 검증**을 실행합니다. 양쪽 모두 NULL·빈 문자열·중복 KEY가 없어야 비교할 수 있습니다.

KEY 규칙은 검증과 실제 레코드 연결에 동일하게 적용됩니다. 예를 들어 앞뒤 공백을 무시하면 `"1 "`과 `"1"`은 같은 KEY입니다.

| 설정 변경 | KEY 검증 | 기존 비교 결과 |
|---|---|---|
| 일반 컬럼의 비교 규칙·SQL 식만 변경 | 유지 | 초기화. SQL 식은 **변환식 확인** 후 **비교 실행** |
| KEY 선택·KEY의 비교 규칙·SQL 식·컬럼 매핑 변경 | 재검증 필요 | 초기화 |
| 파일 재선택·제거, SQL 적용·원본 복원 | 재검증 필요 | 초기화 |
| SQL 테이블명만 변경 | 유지 | 유지 |

### 컬럼별 매핑 룰 검증

**사용자 정의 SQL 식**은 Source에만 적용합니다. 원본 데이터를 수정하지 않고 변환 기대값을 별도 계산한 뒤 Target 값과 문자열 기준으로 그대로 비교합니다. 전체 파일의 **SQL로 가공**을 먼저 적용했다면, 가공된 Source 데이터를 기준으로 식을 계산합니다.

```sql
-- 전표번호 첫 자리를 C로 변경
'C' || SUBSTR("전표번호", 2)

-- 계정원장번호 앞 4자리 뒤에 C 삽입
SUBSTR("계정원장번호", 1, 4) || 'C' || SUBSTR("계정원장번호", 5)

-- 같은 삽입 규칙을 정규식으로 표현
REGEXP_REPLACE("계정원장번호", '^(.{4})(.*)$', '\1C\2')
```

문자열 연결은 `+` 대신 `||`를 사용하며 `SUBSTR` 위치는 1부터 시작합니다. Source의 다른 컬럼을 참조하는 `CASE` 등의 식도 사용할 수 있습니다. 전체 `SELECT`문이나 명령문, 주석, 집계·윈도 함수·행 확장·서브쿼리는 사용할 수 없습니다. 잘못된 식과 미리보기 범위 밖의 변환 오류도 해당 행에 표시하고 비교 실행을 막습니다.

KEY 컬럼에 식을 지정하면 변환된 KEY로 NULL·빈 문자열·중복을 검증하고 Target KEY와 연결합니다. 결과 목록의 해당 KEY는 변환값으로 표시하며, 상세 표에서는 **Source 원본값 / 변환 기대값 / Target 실제값**을 함께 볼 수 있습니다. 변환된 KEY가 중복되면 비교할 수 없습니다.

### 3.4 비교 결과 확인과 다운로드

**비교 실행**을 누르면 Source·Target 행 수와 상태별 건수가 표시됩니다. 건수 카드를 누르면 해당 상태만 조회하며, 페이지당 50건을 표시합니다. 행을 클릭하거나 키보드 Enter·Space로 선택하면 오른쪽에서 컬럼별 값을 비교할 수 있습니다.

| 상태 | 판정 기준 |
|---|---|
| 일치 `MATCH` | 같은 KEY의 매핑된 일반 컬럼이 지정 규칙에 따라 모두 같음 |
| 변경 `MODIFIED` | 같은 KEY의 매핑된 일반 컬럼 중 하나 이상 다름 |
| 추가 `ADDED` | Target에만 KEY가 존재 |
| 삭제 `DELETED` | Source에만 KEY가 존재 |

표시 순서는 Source 파일 순서이며, 추가 데이터는 그 뒤에 Target 파일 순서로 표시됩니다. 상세 표는 존재하지 않는 쪽을 **없음**으로 표시하고, 변경된 컬럼을 강조합니다. 사용자 정의 SQL 식이 있으면 변환 기대값 열도 표시합니다.

| 다운로드 | 포함 내용 |
|---|---|
| 전체 결과 | 상태, KEY, 변경 컬럼 목록, 비교 컬럼별 Source·Target 값 |
| 추가 데이터 | Target에만 있는 행의 전체 컬럼 |
| 삭제 데이터 | Source에만 있는 행의 전체 컬럼 |
| 변경 데이터 | KEY, 컬럼명, Source 값, Target 값. 변경 컬럼마다 1행 |

전체 결과 다운로드는 SQL 변환을 설정한 컬럼의 `SOURCE`·`EXPECTED`·`TARGET` 값을 함께 포함하며, 변환 KEY도 이 세 값을 추가로 제공합니다. 변경 데이터 다운로드에는 사용자 정의 SQL 식이 있을 때 `EXPECTED_VALUE` 열을 추가합니다. 기존 KEY 열은 원본 추적을 위해 Source 원본값(추가 행은 Target 값)을 유지합니다. 컬럼별 변환식은 추가·삭제 다운로드의 원본값을 변경하지 않습니다. 전체 파일에 SQL 가공을 적용했다면 추가·삭제 다운로드도 가공 결과의 전체 컬럼을 사용합니다. 건수가 0인 유형은 다운로드할 수 없습니다. 파일명은 현재 구현의 `dataCompare_<구분>_YYYYMMDD_HHMMSS.csv` 형식을 사용하며, `<구분>`은 `ALL`·`ADDED`·`DELETED`·`MODIFIED`입니다.

### 3.5 여러 파일 쌍 일괄 검증

1. 상단 **일괄 검증** 탭을 선택하고 **+ 파일 쌍 추가**로 필요한 작업을 등록합니다.
2. 작업명과 Source·Target CSV, 헤더 유무를 지정합니다.
3. 각 작업의 **설정하기**를 눌러 모달에서 KEY와 비교 컬럼을 지정합니다. 기존 비교 규칙과 사용자 정의 SQL 식을 사용할 수 있으며 설정은 자동 반영됩니다. **설정 완료**·**닫기** 또는 Esc 키로 목록으로 돌아갑니다.
4. **일괄 검증 실행**을 누릅니다. 파일 쌍을 순서대로 불러와 KEY 검증과 비교를 수행합니다. 특정 작업에 오류가 있으면 실패 사유를 기록하고 다음 작업을 계속합니다.
5. 완료 후 **결과 Excel 다운로드**를 누릅니다. 중단을 요청하면 현재 작업을 마친 뒤 남은 작업을 실행하지 않고 처리 내역을 제공합니다.

| Excel 시트 | 기록 내용 |
|---|---|
| 검증 요약 | 작업명·파일명·처리 상태·일치/변경/추가/삭제 건수·오류 내용. 실패 작업의 건수는 빈칸으로 표시 |
| 불일치 상세 | 변경된 컬럼과 추가·삭제 행의 매핑 컬럼, KEY(JSON), 데이터 행 번호, Source 원본·변환 기대값·Target 값 |
| 검증 기준 | 작업별 헤더 유무·KEY·컬럼 매핑·비교 규칙·SQL 변환식 |

일치 행은 상세 시트에 포함하지 않습니다. NULL·빈 문자열·행 없음은 각 값 옆의 상태 열로 구분합니다. 데이터 행 번호는 헤더를 제외하고 1부터 시작합니다. 불일치 상세는 시트당 1,048,576행을 초과하면 자동으로 시트를 나누며, 32,767자를 넘는 셀이 있는 작업은 실패 처리해 부분 상세 기록을 제거합니다. Excel에는 숫자로 보이는 원본도 문자열로 기록하므로 앞자리 0과 수식처럼 시작하는 텍스트를 보존합니다.

단일 검증과 일괄 검증은 서로 다른 DuckDB 인스턴스를 사용해 탭 전환 시 파일·설정·결과를 유지합니다. 브라우저 새로고침 시에는 초기화됩니다. 일괄 검증은 파일별 SQL 조회문 가공을 제공하지 않으며 컬럼별 SQL 변환식을 지원합니다. 전체 불일치 결과는 Excel 생성 중 메모리에 보관하므로 파일 수나 불일치 건수가 크면 나누어 실행하는 것이 좋습니다.

### 3.6 비교 기준 템플릿 저장·불러오기

같은 구조의 파일을 반복 검증할 때 컬럼 매핑을 다시 작성하지 않도록 비교 기준을 JSON 템플릿으로 저장할 수 있습니다. 저장과 불러오기는 **컬럼 매핑 표 오른쪽 위**에 나란히 배치되어 있습니다. 단일 검증과 일괄 검증에서 같은 형식의 파일을 사용합니다.

1. KEY·컬럼 매핑·비교 규칙·사용자 정의 SQL 변환식을 설정합니다.
2. 컬럼 매핑 표 오른쪽 위의 **템플릿 저장**을 누르면 파일명 입력창이 열립니다. 파일명을 입력하면 `.json` 확장자를 붙여 다운로드하며, 취소하면 저장하지 않습니다. 단일 검증은 Source 파일명을, 일괄 검증은 현재 작업명을 기본 이름으로 제안합니다. 불러온 템플릿의 이름도 이어서 사용할 수 있습니다.
3. 다음 검증 때 Source·Target CSV를 선택하고, 컬럼 매핑 표 오른쪽 위의 **템플릿 불러오기**로 저장한 `.json` 파일을 선택합니다. 일괄 검증에서는 해당 작업의 설정 모달 안에 있습니다.
4. 단일 검증에서는 SQL 변환식의 **변환식 확인**과 **KEY 검증**을 다시 수행한 뒤 비교합니다. 일괄 검증에서는 모달을 닫고 실행하면 각 작업을 다시 검증합니다.

템플릿에는 이름·형식 버전·매핑 순서·Source/Target 컬럼명·KEY 여부·비교 규칙·컬럼별 SQL 변환식이 포함됩니다. 매핑에서 제외한 컬럼은 불러온 뒤에도 제외됩니다. CSV 데이터와 파일 경로, 이전 검증 결과는 포함하지 않습니다. 헤더 유무·SQL 테이블명·파일 전체에 적용한 SQL 조회문은 저장 범위에 포함되지 않으므로 필요한 경우 먼저 해당 조건을 설정하고 가공한 뒤 템플릿을 적용하세요.

필요한 컬럼명이 현재 파일에 정확히 존재해야 적용할 수 있습니다. 추가 컬럼이 있어도 적용할 수 있지만 템플릿에 매핑되지 않았다면 비교에서 제외됩니다. 누락 컬럼·잘못된 JSON·지원하지 않는 버전·중복 매핑 등을 발견하면 구체적인 오류를 표시하며 기존 설정과 결과를 유지합니다. 정상 적용 시에는 현재 KEY 검증·변환식 미리보기·비교 결과를 초기화합니다. 템플릿 파일은 1MB 이하로 제한합니다.

`samples/mapping_rule_template.json`은 전표번호 첫 자리 교체와 계정원장번호 중간 C 삽입을 설정한 예시입니다. `mapping_rule_source.csv`·`mapping_rule_target.csv`와 함께 사용할 수 있습니다.

## 4. 데이터 해석 기준

### 입력과 출력

- 입력은 **UTF-8 인코딩, 쉼표 구분 CSV**입니다. 큰따옴표 인용, 인용 내부 줄바꿈·쉼표·따옴표를 지원합니다.
- 모든 컬럼을 문자열로 읽어 `001`, `01000`, `1.00` 등의 표기를 보존합니다. SQL에서 값을 명시적으로 변환하면 해당 가공 결과를 사용합니다.
- 비인용 빈 필드는 **NULL**, 인용된 `""`는 **빈 문자열**입니다. 문자열 `NULL`은 별도의 텍스트 값입니다.
- 기본 제공 규칙은 NULL과 빈 문자열을 서로 다르게 판정합니다. 사용자 정의 SQL 식은 식의 계산 결과를 비교하므로 `COALESCE` 등으로 명시적으로 NULL을 바꾸면 그 기대값을 사용합니다.
- 비교 규칙은 비교에만 적용합니다. 화면과 다운로드에는 비교 규칙으로 정규화하기 전의 값이 표시됩니다.
- 출력은 UTF-8 BOM을 포함합니다. NULL은 빈 필드, 빈 문자열은 `""`로 기록합니다. CSV를 파싱하므로 입력 파일의 바이트 자체를 그대로 복제하는 방식은 아닙니다.

### 컬럼별 비교 규칙

| 규칙 | 같다고 보는 예 | 유의 사항 |
|---|---|---|
| 앞뒤 공백 무시 — 기본 | `홍길동 ` = `홍길동` | 앞뒤 공백을 제거. 탭은 제거 대상이 아님 |
| 그대로 | 완전히 같은 문자열 | 공백과 숫자 표기를 포함해 그대로 비교 |
| 사용자 정의 SQL 식 | `A001` → `C001` | Source 변환 기대값을 Target과 문자열 기준으로 비교 |
| 숫자 | `10,000` = `10000.00` | 콤마 제거 후 숫자로 비교 |
| 날짜 | `2026-10-01` = `2026.10.01` = `20261001` | 연·월·일 순서, `-`·`.`·`/` 구분자 지원. 유효한 시간이 포함되어 있어도 날짜만 비교 |
| 일시 | `2026-10-01 09:00` = `2026/10/01T09:00:00` | 날짜와 시간 비교. 날짜만 있으면 자정으로 처리. 소수초 지원 |

숫자·날짜·일시로 변환하지 못한 값은 원본 문자열로 비교합니다. 숫자 규칙은 `DOUBLE`을 사용하며, 콤마를 제거한 문자열 길이가 15자를 넘으면 정밀도 손실을 줄이기 위해 원본 문자열로 비교합니다. 날짜·일시는 연·월·일 순서만 지원하며, 잘못된 날짜와 시간대 표기는 변환하지 않습니다.

## 5. 실행 환경과 데이터 처리 구조

| 항목 | 기준 |
|---|---|
| 브라우저 | 데스크톱 Chrome에서 검증. Edge는 배포 대상 환경에서 별도 확인 필요 |
| 화면 | 최소 작업 폭 1100px. 모바일 대응 제외 |
| 메모리 | 개발 PC의 과거 대용량 측정 기록을 바탕으로 16 GB 이상 권장. 파일·SQL·다운로드 크기에 따라 사용량 증가 |
| 서버 | HTML·JS·CSS·이미지·WASM·Worker를 제공하는 정적 HTTP(S) 서버 |
| 개발 도구 | Node.js 22.12 이상 또는 20.19 이상, npm. 최근 개발 검증은 Node.js 24 사용 |

처리 흐름은 **파일 선택 → 브라우저 내 적재·SQL 가공 → KEY 검증 → 비교 → 결과 조회·다운로드**입니다. 입력 파일은 File 핸들로 등록하며 CSV 전체를 JavaScript 행 배열로 만들지 않습니다. DuckDB 테이블은 브라우저 메모리를 사용하고, 화면에는 미리보기 20행 또는 결과 50행만 전달합니다. 다운로드는 비교 결과 10만 행 단위로 생성한 CSV 조각을 Blob으로 합쳐 제공합니다.

- 앱 실행에 외부 CDN·웹 폰트·외부 API가 필요하지 않습니다. 로고 이미지도 빌드에 포함합니다.
- 두 WASM 번들(EH·MVP)과 Worker를 로컬 자산으로 배포하고, 브라우저에 맞는 번들을 선택합니다. 단일 Worker를 사용하며 멀티스레드용 COOP·COEP 설정은 요구하지 않습니다.
- 새로고침하면 데이터·비교 결과·SQL·테이블명 설정은 초기화됩니다. 영구 저장과 세션 복구 기능은 없습니다.
- 로딩·검증·비교·조회·다운로드 중에는 관련 입력과 실행 버튼을 비활성화합니다.

## 6. 빌드와 폐쇄망 배포

### 빌드

의존성을 확보할 수 있는 개발 환경에서 다음 명령을 실행합니다.

```sh
npm ci
npm run build
```

폐쇄망에서 직접 빌드하려면 의존성과 npm 캐시를 미리 준비해야 합니다. 운영 시에는 `dist/` 전체만 내부 웹 서버에 배치합니다. 현재 빌드 크기는 약 72 MiB이며 대부분은 WASM 파일입니다. `.wasm` 또는 Worker 파일을 누락하지 않도록 `dist/`를 통째로 배포합니다.

- 하위 경로 배포를 지원합니다. 예: `https://내부서버/migration-check/`.
- `.wasm`의 응답 MIME은 `application/wasm`으로 설정합니다.
- `index.html`은 재검증하도록 캐시를 설정하고, 파일명이 해시된 `assets/`는 장기 캐시할 수 있습니다.
- WASM·JavaScript 압축 전송을 사용하면 최초 로딩 전송량을 줄일 수 있습니다.
- 사내 CSP를 사용한다면 같은 출처 Worker와 WASM 실행을 허용해야 합니다. 기본 구성 예시는 `script-src 'self' 'wasm-unsafe-eval'; worker-src 'self'`이며, 실제 정책에서 별도 확인합니다.

### 서버 설정 예시

Nginx는 `mime.types`에 `application/wasm wasm;`이 있는지 확인한 뒤 적용합니다. 다음은 루트 경로에 배포하는 예시입니다.

```nginx
server {
    listen 80;
    root /var/www/migration-check;
    include mime.types;
    gzip on;
    gzip_types application/wasm application/javascript text/css;

    location = /index.html {
        add_header Cache-Control "no-cache";
    }
    location /assets/ {
        add_header Cache-Control "public, max-age=2592000, immutable";
    }
}
```

IIS는 다음 MIME 설정을 `dist/web.config`에 추가할 수 있습니다.

```xml
<configuration>
  <system.webServer>
    <staticContent>
      <remove fileExtension=".wasm" />
      <mimeMap fileExtension=".wasm" mimeType="application/wasm" />
    </staticContent>
  </system.webServer>
</configuration>
```

### 로컬 실행

```sh
# 개발 서버 — 기본 포트 5173, 사용 중이면 다른 포트 사용
npm run dev

# 빌드 결과 확인 — 기본 포트 4173
npm run preview

# 또는 dist 폴더를 Python 정적 서버로 제공
python3 -m http.server 8080 --bind 127.0.0.1 --directory dist
```

`index.html`을 더블클릭하는 `file://` 실행은 Worker·WASM 관련 브라우저 보안 제약으로 지원하지 않습니다. 로컬에서도 HTTP 서버로 접속합니다.

10만 행 테스트 데이터는 통합 테스트 실행 중 생성합니다. 과거의 100만 행·파일당 약 100 MB 성능 측정 기록은 [검증·성능 이력](docs/validation-history.md)에 분리했습니다. 해당 값은 개발 PC의 당시 측정 결과이며 현재 버전·사용자 PC·회사 환경에서의 성능 보증이 아닙니다. 현행 UI에서 파일당 약 100 MB 규모의 성능은 다시 측정하지 않았으며, 기존 `tests/benchmark.mjs`는 화면 선택자 갱신과 측정용 파일 준비 후 사용해야 합니다.

### 회사 배포 환경 확인 항목

- [ ] 대상 PC·브라우저에서 엔진 준비 완료와 곡옥 아이콘의 로컬 로딩 확인
- [ ] 내부 서버 외 요청이 없고 `.wasm` MIME이 `application/wasm`인지 확인
- [ ] 기본 샘플의 판정 건수·다운로드 4종·한글·NULL·빈 문자열 확인
- [ ] 실제 데이터와 유사한 크기·컬럼 수·SQL로 처리 시간과 메모리 사용량 측정
- [ ] 사내 CSP·브라우저 보안 정책과 새로고침 후 상태 초기화 확인

## 8. 제약과 확인 범위

- 입력은 UTF-8·쉼표 구분 CSV만 지원합니다. Excel 파일 직접 읽기, EUC-KR 변환, 구분자 선택은 제공하지 않습니다.
- DB 직접 연결, 데이터 수정·이행 실행, 영구 저장, 작업 이력, 실행 중인 개별 쿼리의 강제 취소 기능은 없습니다. 일괄 검증은 현재 작업 완료 후 남은 작업의 실행을 중단할 수 있습니다.
- 데이터 전체와 SQL 원본·가공 결과, 사용자 정의 식의 기대값, 다운로드 Blob이 메모리를 사용합니다. 32비트 WASM의 주소 공간과 브라우저 메모리에 제한이 있으므로 파일 크기만으로 처리 가능 범위를 보장하지 않습니다.
- 중복·빈 헤더는 CSV 엔진이 이름을 자동 보정할 수 있습니다. 헤더만 있는 파일은 엔진의 CSV 추론 결과에 따릅니다.
- 긴 값은 표에서 일부가 잘려 보일 수 있습니다. 미리보기는 앞 20행이며 전체 데이터 정합성을 대표하는 표본은 아닙니다.
- 숫자·날짜·일시 비교는 앞서 정의한 형식과 변환 기준에 한정합니다. 시간대 변환·업무 코드 변환·모든 공백 문자 제거는 자동 수행하지 않습니다.
- 실제 회사 폐쇄망 서버, 대상 사용자 PC와 Edge, MVP 전용 구형 브라우저에서의 실행은 별도 확인 대상입니다.
